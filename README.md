# АИС букмекерской конторы

Учебный проект по дисциплине «Основы программной инженерии» (ГУАП, гр. 4434, вариант 22).

Цель проекта — автоматизированная информационная система (АИС) букмекерской конторы: регистрация клиентов,
ведение линии событий и коэффициентов, приём и расчёт ставок, денежные операции, контроль рисков и отчётность.

На этапе I лабораторной работы № 2 репозиторий используется для отработки процесса командной разработки:
задачи ставятся в Redmine, код ведётся по модели ветвления Git Flow.

## Состав репозитория

| Файл | Назначение |
|------|------------|
| `client_service.py` | ClientService — аутентификация клиентов (проверка логина и пароля) |
| `line_service.py` | LineService — линия событий и коэффициенты |
| `bet_service.py` | BetService — приём ставок и выборка ставок клиента |
| `release_notes.txt` | заметки к выпуску |
| `LICENSE` | лицензия |

## Пример использования

```python
from client_service import ClientService
from line_service import LineService
from bet_service import BetService

clients = ClientService()
lines = LineService()
bets = BetService()

if clients.authenticate("ivanov", "secret"):
    lines.add_line(event_id=101, odds=1.85)
    print(lines.get_odds(101))                      # 1.85
    bets.place_bet(user_id=1, amount=500, event_id=101)
    print(bets.get_user_bets(1))                    # [{'user': 1, 'amount': 500, 'event': 101}]
```

## Планируемые подсистемы

Дерево задач проекта ведётся в Redmine. На этапе II планируется реализовать:

- **ClientService** — регистрация и идентификация клиентов;
- **LineService** — линия событий и коэффициенты;
- **BetService** — приём и учёт ставок;
- **SettlementService** — расчёт ставок по результатам событий;
- **WalletService** — денежные операции и налог;
- **RiskService** — лимиты и выявление подозрительной активности;
- **ReportService** — отчётность;
- **IntegrationService** — ЕЦУПИС, провайдер спортивных данных, платёжный шлюз.

## Модель ветвления Git Flow

| Ветка | Создаётся от | Сливается в | Назначение |
|-------|--------------|-------------|------------|
| `main` | — | — | стабильные выпуски, каждый помечен тегом |
| `develop` | `main` | — | интеграция готовых функций |
| `feature/<N>-<имя>` | `develop` | `develop` | разработка функции по задаче № N |
| `release/<версия>` | `develop` | `main`, `develop` | подготовка выпуска, исправление ошибок тестирования |
| `hotfix/<N>-<имя>` | `main` | `main`, `develop` | срочное исправление выпущенной версии |

### Порядок работы над задачей

```bash
git checkout develop && git pull
git checkout -b feature/4-settlementservice
# ... изменения ...
git add .
git commit -m "Implement SettlementService refs #4"
git push -u origin feature/4-settlementservice
# после проверки:
git checkout develop
git merge --no-ff feature/4-settlementservice
git push origin develop
```

### Сообщения коммитов

- `refs #N` — коммит относится к задаче Redmine № N;
- `fixes #N` — коммит выполняет задачу № N, задача переводится в закрытый статус;
- слияния выполняются с ключом `--no-ff`, чтобы в истории сохранялась структура веток.
